# تطبيق وعد في المتاجر — دليل خطوة بخطوة

كل الملفات جاهزة هنا، وتنتظر **الدومين الخاص** (المخطط له في ديسمبر 2026). التطبيق نفسه هو نظام وعد على الويب داخل غلاف رسمي:
أي تحديث ننشره للنظام يظهر في التطبيقين تلقائيا، دون إعادة رفع للمتجر (إلا إذا تغيّر الغلاف نفسه).

| المجلد | ما فيه |
|---|---|
| `android/` | إعدادات تطبيق أندرويد (Trusted Web Activity عبر أداة Bubblewrap من Google) وملف إثبات الملكية |
| `ios/` | إعدادات تطبيق الآيفون (Capacitor) وصفحة «لا يوجد اتصال» |
| `store/` | الأيقونات وصورة العرض ولقطات الشاشة ونصوص المتجرين (`listing.md`) |
| `setup.py` | يملأ الملفات بالدومين بأمر واحد |

معرّف التطبيق الافتراضي `sa.waad.app` — **لا يمكن تغييره بعد أول رفع**، فقرره قبل البدء.

---

## الخطوة 0 — بعد ربط الدومين
1. اربط الدومين بـ GitHub Pages (Settings → Pages → Custom domain) وتأكد أن النظام يفتح على `https://DOMAIN/site/app/`.
2. حدّث روابط الموقع والنظام للدومين (مهمة منفصلة تُذكر في ذاكرة المشروع).
3. شغّل:
   ```
   python3 mobile/setup.py --domain DOMAIN
   ```
   إذا صار النظام على `https://DOMAIN/app/` بدل `/site/app/` أضف `--app-path /app/` لكل أوامر `setup.py`.

## الخطوة 1 — Google Play (أندرويد)
**المطلوب منك:** حساب مطوّر في Google Play Console (25 دولارا مرة واحدة)، و Node.js و Java 17 على جهازك.

1. ثبّت الأداة: `npm i -g @bubblewrap/cli` ثم في مجلد `mobile/android`:
   ```
   bubblewrap init --manifest https://DOMAIN/site/app/manifest.webmanifest
   ```
   عند الأسئلة استخدم القيم من `twa-manifest.json` الذي أنشأه `setup.py` (أو انسخه فوق الملف الذي تنشئه الأداة).
   الأداة تطلب إنشاء **مفتاح توقيع** (`waad-upload.keystore`): احفظه وكلمة مروره في مكان آمن خارج المستودع — **لا ترفعه إلى GitHub أبدا**، وبدونه لا تستطيع تحديث التطبيق.
2. `bubblewrap build` ← ينتج `app-release-bundle.aab`.
3. في Play Console: أنشئ تطبيقا، فعّل «Play App Signing»، وارفع الملف في «الاختبار الداخلي» أولا.
4. من Play Console → App integrity انسخ **SHA-256 certificate fingerprint** لمفتاح التوقيع الذي تستخدمه Google، ثم:
   ```
   python3 mobile/setup.py --domain DOMAIN --sha256 AB:CD:...
   ```
   هذا ينشئ `.well-known/assetlinks.json` في جذر المستودع و `.nojekyll`. ارفعهما (commit + push) وتأكد أن `https://DOMAIN/.well-known/assetlinks.json` يفتح.
   بدون هذا الملف يظهر شريط المتصفح أعلى التطبيق.
5. أكمل صفحة المتجر من `store/listing.md` والصور من `store/`، واملأ «أمان البيانات»، ثم أرسل للمراجعة.

## الخطوة 2 — App Store (آيفون)
**المطلوب منك:** حساب Apple Developer (99 دولارا سنويا؛ للمنشأة يحتاج رقم D-U-N-S)، و Xcode و CocoaPods على جهازك الماك، و Node.js.

1. في `mobile/ios`:
   ```
   npm install
   npx cap add ios
   npx cap sync ios
   npx cap open ios
   ```
2. في Xcode: اختر فريقك (Signing & Capabilities)، وضع `store/ios-icon-1024.png` في AppIcon، واجعل اسم العرض «وعد».
3. Product → Archive ← Distribute → App Store Connect، ثم أكمل الصفحة من `store/listing.md` ولقطات `store/iphone/`.

**تنبيه مهم عن قبول Apple:** Apple قد ترفض تطبيقا يعرض موقعا فقط (الإرشاد 4.2 «الحد الأدنى من الوظائف»).
قبل الإرسال نضيف مزايا خاصة بالجوال تجعله تطبيقا فعليا، وأقترح:
- إشعارات أصلية (Push عبر APNs) بدل إشعارات المتصفح — إشعارات الويب لا تعمل داخل غلاف الآيفون؛
- الدخول بالبصمة / Face ID؛
- تصوير الإيصالات والمرفقات بالكاميرا مباشرة.
هذه مهمة تطوير منفصلة عند الوصول لهذه الخطوة.

## ملاحظات
- **الأيقونة:** مولّدة من شعار وعد الموجود في النظام (عرضه 280 بكسل)، فتكبيرها لـ 1024 يفقدها بعض الحدة. للمتاجر يُفضّل أن ترسل لي الشعار بجودة عالية (SVG أو PNG بعرض 2000 بكسل) وأعيد توليد الصور.
- **حذف الحساب:** المتجران يشترطان طريقة لطلب حذف الحساب من داخل التطبيق أو برابط؛ المتاح حاليا عبر «الدعم الفني» للمالك والموارد البشرية للموظف (مذكور في `store/listing.md`).
- **الأسعار:** على الآيفون لا يُعرض داخل التطبيق رابط شراء أو سعر حتى لا يُرفض؛ شريط «اشترك الآن» في النظام يجب إخفاؤه داخل غلاف الآيفون (ضمن مهمة مزايا الجوال أعلاه).
