# فحص الأمان — Security scanning

طبقتان من الفحص الأمني لـ«وعد»:

## 1) اختبارات الاختراق الموجّهة لقاعدة البيانات (الأهم) — جاهزة وتعمل
الملف: `supabase/tests/20_pentest.sql` (يعمل ضمن `supabase/tests/run.sh`).
يلعب دور مهاجم مسجّل، وغريب بلا حساب، وجلسة بكلمة المرور فقط، ومدير المنصة، وزائر مجهول،
ويحاول: اختراق العزل بين المنشآت، رفع الصلاحيات، فتح وحدة مقفلة، تخطّي المصادقة الثنائية،
تجاوز حدود مدير المنصة، تصدير بيانات غيره، والعبث بسجل التدقيق. 39 محاولة، كلها تُصدّ.
هذه الطبقة تغطي مكان الحماية الفعلي في «وعد» (سياسات RLS داخل القاعدة).

## 2) Strix — فاحص هجومي آلي (اختياري، يُشغَّل على جهازك)
`usestrix/strix` وكلاء ذكاء اصطناعي يفحصون الكود كمخترق. لا يُشغَّل في بيئة Claude لأنه
يحتاج Docker يعمل ومفتاح نموذج ذكاء اصطناعي خاص بك (تكلفة عليك). النص `security/run-strix.sh`
يشغّله بأمان على **مجلد المصدر** (لا يلمس الموقع العام ولا Supabase). الخطوات:

```bash
export STRIX_LLM="openrouter/z-ai/glm-5.3"   # أو مزود آخر يدعمه Strix
export LLM_API_KEY="sk-..."                   # مفتاحك أنت
./security/run-strix.sh
```

النتائج تُحفظ في `strix_runs/`. راجع أي نتيجة يذكرها مقابل الطبقة الأولى قبل اعتبارها ثغرة،
لأن كثيراً مما يظنه فاحص خارجي ثغرة يكون مصدوداً أصلاً في سياسات القاعدة.
