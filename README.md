# وعد ERP — الخادم وقاعدة البيانات (المرحلة 1)

قاعدة بيانات حقيقية لنظام وعد: موارد بشرية + رواتب + محاسبة + مبيعات + مشتريات + مخزون، مبنية لتعمل على **Supabase** (Postgres + تسجيل دخول) بخطته المجانية.

## ما الموجود الآن
| الملف | المحتوى |
|---|---|
| `supabase/migrations/0001_core.sql` | المنشآت (أكثر من شركة في نفس النظام)، الأدوار، الترقيم، سجل تدقيق لا يُعدَّل |
| `0002_hr.sql` | الموظفون، أنواع الإجازات، مسارات الاعتماد، التأمينات، نهاية الخدمة، مسير الرواتب، أقساط السلف، العهد |
| `0003_finance.sql` | دليل الحسابات، القيود (متوازنة إجبارياً ولا تُعدَّل)، العملاء والموردون، الأصناف، فواتير البيع والشراء، الإشعارات الدائنة والمرتجعات، السندات، المخزون، التقارير، ضريبة القيمة المضافة |
| `0004_grants.sql` | ما يُسمح للمتصفح باستدعائه فقط |
| `supabase/tests/` | 143 اختباراً آلياً (عزل الشركات، الصلاحيات، الاعتمادات، الرواتب، القيود، المخزون، الضريبة) |

## مبادئ الأمان
- **كل جدول عليه Row Level Security:** الموظف يرى سجله فقط، المدير يرى فريقه، الموارد البشرية ترى الموظفين، المالية ترى الحسابات. شركة لا ترى بيانات شركة أخرى.
- **العمليات الحساسة عبر دوال على الخادم فقط** (اعتماد طلب، فاتورة، سند، مسير). كل دالة تتحقق من دور المستخدم بنفسها، والمتصفح لا يكتب في القيود أو المخزون مباشرة.
- **أدوار المالية:** المدير المالي (`finance`) له كل الصلاحيات. المحاسب (`accountant`) وأمين المخزن (`storekeeper`) لهم صلاحيات يحددها المدير المالي في جدول `finance_permissions` (المبيعات، المشتريات، المخزون، القيود، التقارير، الضريبة، الرواتب...). قيود الرواتب والسلف مخفية عن أي دور لا يملك صلاحية `payroll`.
- **لا أحد يعتمد طلبه.** الموارد البشرية تُعدّ المسير والمالية/المدير العام يعتمده.
- **القيود والمخزون وسجل التدقيق وسجل الاعتمادات لا تُعدَّل ولا تُحذف.** التصحيح بقيد عكسي أو إلغاء المستند.

## التشغيل المجاني على Supabase
1. أنشئ حساباً مجانياً على supabase.com ثم مشروعاً جديداً (اختر أقرب منطقة متاحة).
2. من **SQL Editor** شغّل ملفات `supabase/migrations` بالترتيب: 0001 ثم 0002 ثم 0003 ثم 0004.
3. من **Authentication** فعّل الدخول بالبريد، وأنشئ مستخدمك الأول.
4. بعد تسجيل الدخول من الواجهة يستدعي المستخدم `create_company('اسم المنشأة')` فيصبح مالكها ويُنشأ دليل الحسابات تلقائياً.
5. المفتاح العام (anon key) يوضع في الواجهة، **ومفتاح service_role لا يوضع في الواجهة أبداً**.

> مهم: الخطة المجانية تستضيف خارج المملكة، وتتوقف المشاريع غير النشطة. استخدمها للتطوير ببيانات وهمية فقط. قبل إدخال بيانات موظفين حقيقية راجع متطلبات نظام حماية البيانات الشخصية (نقل البيانات خارج المملكة) مع مختص.

## غير مُنفَّذ بعد
- الواجهة المتصلة بقاعدة البيانات (المرحلة التالية: نقل شاشات النموذج إلى Supabase).
- الإهلاك الآلي، الإقفال السنوي، الإشعارات الدائنة.

- القواعد النظامية (الإجازات، نهاية الخدمة، نسب التأمينات) من مصادر ثانوية — راجع `docs/RULES.md` واعتمدها مع مختص قبل التشغيل الفعلي.

## The real app (app/waad-app.html)
Single self-contained file connected to Supabase (URL + publishable key inside — safe for browsers; RLS protects data).
Open it directly in a browser, or upload it to any static host (Netlify/Vercel/GitHub Pages).
- Sources: app/src/*.js|css → `python3 app/build.py` → app/waad-app.html
- Accounts: owner signs up → creates company. Staff: HR invites by email → person gets an 8-char code → signs up with the same email → enters the code.
- Tests: `devserver/start.sh app` (local Postgres + Supabase API emulator) then `python3 app/tests/e2e_app.py` (55 checks). DB: `supabase/tests/run.sh` (167 checks).
- Migration 0005_invites.sql adds invitations + owner-protection guard; run build/0005_invites.sql in the SQL Editor.
